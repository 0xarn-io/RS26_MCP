# Virtual-controller I/O SDK evidence

Verified against `C:\Program Files (x86)\ABB\RobotStudio 2026\Bin\ABB.Robotics.Controllers.PC.dll`, assembly version `26.3.11844.1`, using read-only reflection and the ABB public API documentation. No controller was instantiated or contacted during this investigation.

- [Signal](https://developercenter.robotstudio.com/api/pcsdk/api/ABB.Robotics.Controllers.IOSystemDomain.Signal.html) exposes writable `Value` and `InputAsPhysical`. ABB describes `InputAsPhysical` as simulated physical-input setting for a virtual controller; enabling it bypasses the configured signal access-level check. The bridge permits it only on an input owned by the selected local station virtual controller, captures the flag for one request, and restores the wrapper flag afterward. Ordinary input writes with `simulateInput:false` remain subject to SDK/controller access checks.
- [SignalState](https://developercenter.robotstudio.com/api/pcsdk/api/ABB.Robotics.Controllers.IOSystemDomain.SignalState.html) exposes read-only `Value`, `Simulated`, and `Quality`. There is no public `Simulated` setter or general force/release method on the inspected signal classes. `InputAsPhysical` is distinct from `State.Simulated`; these operations do not claim persistent forcing.
- [GroupSignal](https://developercenter.robotstudio.com/api/pcsdk/api/ABB.Robotics.Controllers.IOSystemDomain.GroupSignal.html) supplies `uint` `GroupValue`, `GroupMinValue`, and `GroupMaxValue`. The bridge uses these rather than the legacy float properties, so values such as `4294967295` retain all 32 bits. Digital writes accept only zero or one; analog writes must fit configured bounds and finite single precision. All requested values and metadata bounds are validated before mutation.
- [DigitalSignal.Pulse(int)](https://developercenter.robotstudio.com/api/pcsdk/api/ABB.Robotics.Controllers.IOSystemDomain.DigitalSignal.html) takes milliseconds. Installed managed IL forwards the requested duration, the captured `InputAsPhysical` flag and `Log` flag to the SDK adapter. The adapter constructs a native pulse request (`Delay=0`, active/passive pulse lengths equal to the duration, `PulseNo=1`) and waits on the `IRobIO.WriteIOSignal` request task. No managed delay, timer, or subsequent reset callback is created. Consequently the bridge uses the native pulse API and disposes the wrapper after submission; the response explicitly reports `pulseRequested:true, completed:false`. Native request acknowledgement is not evidence that the pulse elapsed. As with ordinary PC SDK writes, the API call itself performs a synchronous request/acknowledgement; the bridge adds no timing wait on RobotStudio's main thread.
- [IOSystem](https://developercenter.robotstudio.com/api/pcsdk/api/ABB.Robotics.Controllers.IOSystemDomain.IOSystem.html) exposes `GetSignal` and `GetSignals(IOFilterTypes.All)`. Named reads preserve request order and report individual lookup/read failures. Inventory reads sort and page the result, and dispose all signal wrappers, including those outside the selected page. Values and state metadata are observations, not an atomic controller snapshot.

All operations reuse the existing checked `OwnedVirtualTask`, `OpenOwnedVirtualConnection`, and `EnsureOwnedVirtualContext` path. They never discover controllers, accept addresses, create a standalone connection, start/stop RAPID, or stop station simulation. Writes check station identity and the local virtual connection immediately before invoking the SDK. A running virtual program may immediately overwrite a written value or affect pulse observations. The after-value is therefore readback evidence only, not a guarantee of a held value. Any failed acknowledgement or post-write readback explicitly warns that the operation may already have happened and should not be blindly retried.
