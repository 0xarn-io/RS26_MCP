# Station previews and undoable target edits

`preview_targets` resolves each named target or explicit robtarget inside the selected station robot's task. Explicit poses are relative to the specified work object's object frame. The existing tested double-precision frame maths composes that frame into station world coordinates; SDK drawing receives metres. Preview frames show the TCP coordinate systems, so a tool definition is unnecessary. Joint targets are not accepted and no robot is moved.

A station `RsRobTarget` declaration can exist without a graphical `RsTarget`: ABB's [RsTarget constructor example](https://developercenter.robotstudio.com/api/robotstudio/api/ABB.Robotics.RobotStudio.Stations.RsTarget.html) adds the declaration and graphical target to separate collections. Named pose operations and previews now prefer existing graphical targets, then consider a unique station declaration only when no graphical name matches. Declaration fallback requires an explicit work object and creates only a detached wrapper, without adding station objects or synchronizing data. A graphical target bound to another work object cannot be bypassed through the fallback. `edit_targets` continues to require an existing graphical target when updating data.

Inspection of the installed SDK IL found that `RsTarget` construction registers a reference on its supplied robtarget and changes that robtarget's configuration status, even before collection insertion. The fallback therefore copies the declaration's numeric frame, configuration and external-axis values into a fresh `RsRobTarget` first. It retains the original declaration only for identity, ownership and value-change checks across asynchronous IK. The work-object setter does not mutate the supplied work object or register a work-object backreference.

The SDK-free declaration-selector tests cover graphical bindings, unbound declarations and ambiguous names.

ABB's [TemporaryGraphicCollection](https://developercenter.robotstudio.com/api/robotstudio/api/ABB.Robotics.RobotStudio.Stations.Forms.TemporaryGraphicCollection.html) documents `DrawFrame(Matrix4, double, double, string, int)` and `DrawLineStrip(IEnumerable<Vector3>, double, Color)`. [Temporary Graphics](https://developercenter.robotstudio.com/api/robotstudio/articles/How-To/Visualization/TemporaryGraphicsExample.html) demonstrates removing one graphics handle with `station.TemporaryGraphics.Remove(handle)`. The bridge retains only its own handles in a weakly keyed per-station collection. Showing another preview replaces those handles; clearing removes only those handles. It never calls a collection-wide clear or removes another add-in's graphics. Frames and connecting lines are visual aids, not reach or collision validation and not an interpolated robot trajectory.

`edit_targets` prevalidates the entire batch before modifying station objects. Existing target edits retain their `RsRobTarget` declaration and referring path instructions. New target creation requires `create:true`, a valid unused RAPID name, and an explicit work object. Names can be `name` or `Module/name`; unqualified new declarations retain an empty module assignment for the owner's later station workflow. No name is silently adjusted. One declaration cannot be edited twice in the same batch. A declaration with multiple graphical target instances is refused to avoid moving unspecified shared uses. Reassigning a referenced target to another work object is refused because its move-instruction arguments would also require review; changing its pose in the existing work object remains supported.

ABB's [Creating Targets](https://developercenter.robotstudio.com/api/robotstudio/articles/How-To/Targets-and-Paths/g_CreateTarget.html) shows adding an `RsRobTarget` to `RsTask.DataDeclarations`, then an `RsTarget(workObject, robTarget)` to `RsTask.Targets`. [Transforming Target](https://developercenter.robotstudio.com/api/robotstudio/articles/How-To/Transform/TransformTarget.html) confirms that the local target matrix is expressed with respect to the work object. [RsTask](https://developercenter.robotstudio.com/api/robotstudio/api/ABB.Robotics.RobotStudio.Stations.RsTask.html) exposes `IsValidRapidName`, `IsValidRapidNameInTaskScope` and `FindTargetsByRobTarget`; [RsDataDeclaration](https://developercenter.robotstudio.com/api/robotstudio/api/ABB.Robotics.RobotStudio.Stations.RsDataDeclaration.html) exposes the referencing instructions.

All edits run in one synchronous main-thread undo transaction. SDK exceptions roll the transaction back using ABB's documented `CancelUndoStep(Rollback)` / `EndUndoStep` pattern. Successful edits can be reversed with the owner's RobotStudio Undo action. Both operations require stopped simulation. Moving work objects and specified external-axis positions are refused rather than approximated. Neither operation synchronizes data to a controller, saves the station, loads or restarts RobotStudio, or creates a controller connection.

The request limits are 100 preview points and 50 target edits, enforced by the shared SDK-free request parser. Offline validation tests cover request shape and frame math; graphics visibility, SDK undo/rollback, name-scope checks and reference handling require owner-loaded RobotStudio verification. No live preview or edit is represented as tested before that check runs.
