# Selected station / virtual-controller data operations

The bridge compares selected scalar `robtarget`, `tooldata` and `wobjdata` values without synchronizing. It uses the public PC SDK only to obtain a wrapper around RobotStudio's **existing** station-virtual-controller connection. It never scans for controllers, adds connections, supplies an address, logs on/off, starts a virtual controller, or accesses a real controller.

Before `Controller.Connect`, the selected mechanism task must belong to exactly one `Station.VirtualControllers` entry. Its system GUID must match an existing `ControllerManager.ControllerReferences` entry whose `ControllerType` is `StationVC` and `IsStationController` is true. `ConnectionType.RobotStudio` delegates connection/authentication management to the host; after obtaining the wrapper, the bridge checks `IsVirtual`, loopback IP, GUID and current station/task ownership before reading values.

Verified public documentation:

- [ControllerObjectReference](https://developercenter.robotstudio.com/api/robotstudio/api/ABB.Robotics.RobotStudio.Controllers.ControllerObjectReference.html): controller references expose `SystemId`; the documented way to interact is the PC SDK. `RobControllerConnection` is marked internal use and is not used here.
- [ConnectionType](https://developercenter.robotstudio.com/api/pcsdk/api/ABB.Robotics.Controllers.ConnectionType.html): `RobotStudio` requires the host already be connected and manages authentication through RobotStudio. `Standalone` is deliberately unused.
- [Controller](https://developercenter.robotstudio.com/api/pcsdk/api/ABB.Robotics.Controllers.Controller.html): `Connect(Guid, ConnectionType, bool)`, `IsVirtual`, loopback `IPAddress` for virtual controllers, and disposal.
- [Rapid](https://developercenter.robotstudio.com/api/pcsdk/api/ABB.Robotics.Controllers.RapidDomain.Rapid.html) / [RapidData](https://developercenter.robotstudio.com/api/pcsdk/api/ABB.Robotics.Controllers.RapidDomain.RapidData.html): `GetRapidData(task,module,name)` and read-only use of `Value`, `RapidType`, `IsArray` and `ExecutionStatus`.
- [RsTask](https://developercenter.robotstudio.com/api/robotstudio/api/ABB.Robotics.RobotStudio.Stations.RsTask.html): `SyncDataAsync(dataId,direction,logMessages)` synchronizes an individual declaration. Its documented file-URL alternative is excluded by accepting only validated `Module/name` identifiers.
- [SyncLogMessage](https://developercenter.robotstudio.com/api/robotstudio/api/ABB.Robotics.RobotStudio.Stations.SyncLogMessage.html): message IDs, severities and string arguments are returned for each selected synchronization.

Installed metadata inspection confirmed the required public members in RobotStudio 2026 `Bin`. The apparent `RsTask.GetDataDeclarationFromController` method is assembly-internal, and `VirtualController.ControllerConnection` exposes an internal-use interface; neither is used. Both added assembly references (`ABB.Robotics.Controllers.PC.dll`, `ABB.Robotics.RobotStudio.Controllers.dll`) use `Private=false`.

Comparison exports local RAPID-value frames in millimetres and scalar-first quaternions, target configuration/external axes, complete tool load fields, and work-object hold/programmed/mechanical-unit flags. It compares values, not declaration storage/locality or a graphical target's work-object association. Numeric tolerance is `1e-6 + 1e-7 * max(abs(a),abs(b))` to accommodate PC SDK float fields; configuration values are exact. Unit quaternion components use `1e-6` tolerance and allow sign reversal. The PC SDK's single-precision `9E9` external-axis sentinel is normalized to `9E9`. Difference paths and both snapshots are returned. Missing data on either side is reported. A module-qualified name is required for VC-only data; built-ins with no module are explicitly unsupported.

Synchronization requires an explicit direction and selection of 1–100 declarations, a stopped simulator, and stopped VC RAPID. All selections and source availability are checked before the first write. The bridge calls `SyncDataAsync` once per selected data ID; it never invokes whole-task or path synchronization. It stops the batch on its first failure, returns SDK logs and partial-completion information, and does not retry. Station imports have individual undo steps. Previously completed virtual-controller writes are not rolled back by station Undo. Call `data_compare` before changes and after an error; concurrent owner edits can invalidate a comparison.

Offline tests cover transport shapes, forwarding, and numeric and quaternion comparisons. To verify a selected declaration on a local installation, run `data_compare` and inspect the reported station and virtual-controller values.
